# Политика безопасности

## Как сообщить об уязвимости

Не открывайте публичный issue и не публикуйте подробности в discussions.

Напишите владельцу репозитория в приватном порядке (GitHub → Security → Report a
vulnerability, либо личное сообщение). Опишите:

- что делает уязвимость и при каких условиях;
- версию или коммит;
- шаги воспроизведения;
- **чем вред**: потеря данных, выполнение произвольного кода, обход защиты, отказ в
  обслуживании.

Ожидайте ответа в течение нескольких дней. Исправление выпускается до обсуждения.

## Что особенно важно для этого проекта

MrProper удаляет файлы. Поэтому дефекты приоритетной категории — те, из-за которых
можно удалить пользовательские данные или системные файлы:

- удаление за пределами корня правила (обход проверки пути, символьные ссылки, короткие
  имена 8.3, junction);
- неверная трактовка шаблона правила (`*` пересекает границу каталога, `**` не должен
  совпадать с пустым сегментом, класс символов `[!0-9]`, регистр);
- подмена набора правил из сети: неверная проверка подписи, хеша, отката;
- гонка между проверкой и удалением, отмена не оставляет систему в согласованном
  состоянии;
- утечка за пределы машины: телеметрия, отчёт, который молча уносит серийники.

## Чего нельзя вкладывать в issue и отчёт

Даже «случайный» отчёт содержит приватные данные. Перед отправкой:

- замаскируйте серийники дисков и модель, если это не нужно для разбора;
- проверьте, что в списке найденных кандидатов нет ваших личных каталогов
  (`Downloads`, профили, корпоративные сетевые пути);
- в отчёте есть пути — они уже чувствительны.

## Подписанные сборки

Сборки не подписаны (ADR-009). Проверяйте соответствие хешу из релизных заметок:
подменённая сборка утилиты, которая удаляет файлы, опаснее подменённого правила.

## 5. Что нужно завести отдельными задачами

Не «исправить здесь» — файлы чужие, правило владения запрещает. Список для оркестратора,
по убыванию важности:

1. **Обход ФС в CLI не подключён (код 4).** `scan` не работает: `ScanServices::createProbe`
   не получает мост `engine::FileSystemProbe`. Пока это так, §12-пункты 2, 3, 7 не
   проверяемы, а половина e2e-сценариев проходит вхолостую. Это первая по важности задача.
2. **11 красных интеграционных проверок обхода ФС** (`vfs_walk_tests.cpp`,
   `vfs_edge_tests.cpp`, симптом — Win32 206 на корне). Дефект доинтервальный: базовый
   бинарник из `build\main\Debug` даёт те же провалы. Нужен владелец
   `src/platform/vfs_walk.cpp` + соответствующих тестов.
3. **`tools\test.bat` и CI не запускают интеграционные тесты.** Из-за этого пункт 2
   невидим: и `test.bat`, и шаг CI «Тесты» зовут только `mrproper_unit_tests.exe`. Стоит
   либо расширить контракт `test.bat`, либо добавить в CI шаг `ctest`.
4. **Нет команды отмены в CLI.** `engine::undo_service` (§6.2) из CLI недоступен —
   e2e восстановления проверяет контракт манифеста вместо настоящей отмены.
5. **`CONTRIBUTING.md` отсутствует, `.github/ISSUE_TEMPLATE` пуст** — пункт §12-12 не закрыт
   по документации, это дешёвая правка.
6. **`clang-tidy` не запускаем** ни в одном автоматическом сценарии: нужен пресет
   `ninja-debug` (генератор Ninja пишет `compile_commands.json`).
7. **Эталонные VM.** Пункты 1, 3, 9, 10 и BitLocker без админа закрываются только на
   них; автоматизировать прогон на VM-образах (Pester + `manage-bde` с повышенными правами)
   — отдельная задача.

Критерий задачи одной строкой (это именно та команда, которой зафиксирован вердикт):

```
tools\build.bat Release a98 && tools\test.bat Release a98
```

Интеграционные и e2e — отдельными шагами, они не входят в критерий и в CI:

```
build\a98\Release\mrproper_integration_tests.exe
Invoke-Pester -Script @{ Path = 'tests\e2e\Test-*.ps1';
                        Parameters = @{ Configuration = 'Release'; Slot = 'a98' } }
```

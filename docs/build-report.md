**Прошлое состояние ворот, ради сравнения.** На `c005b39` тот же самый снимок окна давал
**код 4 и `чернила=0`**. Разница за один день — вся волна K1–K3: появился рельс
навигации. Подробный разбор — §2б.

**Что этот прогон НЕ доказывает, и это главное в отчёте.** Число `чернила=41552` в точности
равно числу опробованных пикселей рельса навигации (112 x 371 = 41 552): фон рельса
`(43,43,43)` не совпадает с фоном содержимого `(32,32,32)`, поэтому весь рельс засчитан
воротами как «чернила». Хост содержимого при этом пуст: снимок окна `MrProper.ContentHost`
(896x760) даёт `distinct=1`, `nonbg=0` из 170 240 опробованных пикселей в обоих режимах
`PrintWindow`; повторный замер на пересобранном бинарнике даёт то же в четырёх конфигурациях
окна — §2б.4. То есть ворота замеряют «нарисован рельс», а не «нарисован экран» — **D-60**,
сама находка — **D-59**. Плюс **D-61**: в светлой теме у выделенного пункта рельса не
рисуется подпись — в полосе пункта два цвета и ноль пикселей текста против 301 в тёмной
теме.

**Версия ворот от 04:19:26 считает чернила в хосте содержимого и на том же бинарнике
возвращает код 9 во всех пяти конфигурациях** (чернила хоста `0` при пороге 5000). То есть
находка D-59 сегодня доказана не только попиксельным разбором снимка, но и штатной
проверкой проекта — §2б.5.

* `CMAKE_BUILD_TYPE` генератором Visual Studio **игнорируется** — конфигурация выбирается

  твоему.

## 1a. Сборка Debug, прогон задачи H5 (2026-09-29): сборка не состоялась

Этот раздел стоит первым, потому что он отменяет смысл всех чисел ниже: **свежая сборка
`HEAD` в этом проходе невозможна**, и потому числа разделов 3.x этого прогона описывают
бинарники слотов, а не дерево.

**Почему, по фактам.** В `tools\build.bat` ровно две пробы `vcvars64.bat`, и обе провалились:

| Проба | Ожидаемое | Фактическое |

| `D:\BuildTools\VC\Auxiliary\Build\vcvars64.bat` (строка 30) | каталог `VC` экземпляра BuildTools | **каталога нет.** У экземпляра `2cbeafe3` (`installationPath: D:\BuildTools`, BuildTools 17.14.41) в `state.json` нет пакета `Microsoft.VisualStudio.Component.VC.Tools.x86.x64`; на диске только `Common7`, `Licenses`, `MSBuild` |

окружения вручную даёт `cl.exe`, `cmake.exe` и `ctest.exe` по этим путям. То есть сломано
**обнаружение**, а не компилятор.

**Починить из задачи H5 нельзя.** `mkdir D:\BuildTools\VC\Auxiliary\Build` из Windows

`tools\build.bat` не входит в четыре файла этой задачи. Это заведено как **D-54**

цифры: `чернила=41552 из 207760 точек` стабильно.

## 8. Как повторить

Из корня репозитория, слот — свой (обязательный, иначе агенты делят кэш CMake):

```
tools\build.bat Debug a5
tools\test.bat Debug a5
tools\run-e2e.bat Debug a5
```

Критерий задачи одной строкой (это именно та команда, которой зафиксирован вердикт):

```
cmd.exe /c "tools\test.bat Debug a5"
```

Один e2e-сценарий — третьим аргументом фильтра:

```
tools\run-e2e.bat Debug a5 e2e_FullCycle
```

**общий каталог всех слотов**: время файла важнее его содержимого.

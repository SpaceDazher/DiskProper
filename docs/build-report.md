# Отчёт о сборке и прогоне тестов MrProper

**Свежий прогон: задача G5, 2026-09-29, конфигурация `Debug`, слот `a5`.**
Предыдущий прогон: задача F7, 2026-09-28, слот `a7` — его числа сохранены в §6
как история и **не смешаны со свежими**: база тогда была `90d5032` плюс незакоммиченные
правки, а сегодняшняя — `88bf0b4` плюс незакоммиченная обвязка манифеста (G1).

**Что изменилось в прогоне по сравнению с предыдущим и почему это важно для чтения
чисел.** Три вещи, каждая из которых меняет смысл цифры:

1. **e2e наконец гоняются и ими можно доказать.** В проходе F7 они были
   «не измерено — прогон не завершился в отведённое время», и в этом документе стояла
   честная прочерк вместо числа. Теперь у них есть ворота (`tools\run-e2e.bat` →
   `ctest -L e2e`, регистрация в `tests/CMakeLists.txt`, job `e2e` в CI), и прогон
   завершился: §3.4.
2. **Интеграционный набор стал зелёным.** Было `FAIL: 25 проверок, провалов 3` —
   сегодня `ALL PASS: 25 проверок, провалов 0`.
3. **Утилита перестала быть бесполезной.** `buildPlan` fail-closed давал 0 операций и
   `skipReason=needs-enumeration` у всех кандидатов; после обвязки манифеста (G1)
   `plan` даёт операции. Проверено прямым вызовом CLI, §3.6.

**Честная оговорка о том, что двигалось во время прогона.** Все C++-исходники, попавшие в
слот `a5`, старше бинарников: последний из них изменён в 23:19, а `mrproper_cli.exe`
собран в 00:09:35, `mrproper_unit_tests.exe` — в 00:09:16. **Ни один C++-файл после сборки
не менялся**, поэтому числа §3.1–§3.3 и §3.6 относятся ровно к тому дереву, которое стоит
сейчас. Двигалось другое: в 00:15:59 изменён `tests/e2e/Test-UndoRestore.ps1`, в 00:23:17 —
`tests/e2e/Test-EdgeCases.ps1` (параллельная задача волны, во время моего прогона e2e).
На результат это не повлияло: каждый сценарий читал **свою** версию файла, актуальную на
момент старта, и ни один файл не менялся между своим прогоном и концом этого документа.
Но читать «дерево неподвижно» нельзя — неподвижен был код, а не дерево.

**О чём документ.** Критерий задачи — `tools\build.bat` и `tools\test.bat` плюс отчёт
с числами. Спек-раздел §12 — это 12 пунктов, и честный ответ на них не «всё зелёное»:
четыре из них на одной машине разработчика проверить нельзя в принципе. Ниже сначала
числа сегодняшнего прогона, затем история, затем построчный разбор §12 и список того,
что нужно завести отдельными задачами.

Правок кода в этом документе нет. Четыре файла задачи — `docs/defects.md`,
`docs/dod-checklist.md`, `docs/team-report.md`, `docs/build-report.md`; ничего в `src/`,
`tests/`, `CMakeLists.txt`, `tools/` не менялось.

### 3.4 E2E-сценарии (Pester 4.10.1 через CTest)

Впервые в проекте у e2e есть ворота и, значит, есть числа. Команда:

```
tools\run-e2e.bat Debug a5
```

Она вызывает `tools\test.bat Debug a5 e2e`, а тот — `ctest --test-dir build\a5
-C Debug -L e2e --output-on-failure`. Ключ `-Destructive` не передаётся **никогда**
(см. §1 и комментарий в `tests/CMakeLists.txt`): на машине разработчика кандидаты
настоящего скана — это реальный кэш пользователя.

Фактический вывод:

```
Test project D:/Project/MrProper/build/a5
    Start 1: e2e_BadRules
1/4 Test #1: e2e_BadRules .....................   Passed  302.67 sec
    Start 2: e2e_EdgeCases
2/4 Test #2: e2e_EdgeCases ....................   Passed  224.52 sec
    Start 3: e2e_FullCycle
3/4 Test #3: e2e_FullCycle ....................   Passed  559.10 sec
    Start 4: e2e_UndoRestore
4/4 Test #4: e2e_UndoRestore ..................   Passed   35.49 sec

100% tests passed, 0 tests failed out of 4

Label Time Summary:
e2e    = 1121.78 sec*proc (4 tests)

Total Test time (real) = 1121.84 sec
EXIT=0
```

| Сценарий | Проверок `It` в файле | Результат CTest | Время |
|---|---|---|---|
| `Test-BadRules.ps1` (битые и неподписанные правила) | 5 | **Passed** | 302.67 с |
| `Test-EdgeCases.ps1` (сценарии защиты) | 19 | **Passed** | 224.52 с |
| `Test-FullCycle.ps1` (полный цикл) | 11 | **Passed** | 559.10 с |
| `Test-UndoRestore.ps1` (отмена и восстановление) | 9 | **Passed** | 35.49 с |
| **Итого** | **44** | **4 из 4, 0 провалов** | **1121.84 с** |

**Что здесь честно, а что нет.** «4 из 4 Passed» — это факт CTest. Но:

* это **4 сценария из 20**, которые требует §12.3. В репозитории лежат четыре файла
  `Test-*.ps1` и 44 блока `It`; расхождение «20 сценариев» против «4 файла / 44 It»
  не сведено и остаётся открытым вопросом к спеке.
* «Passed» означает «сценарий не упал», а не «сценарий всё проверил». Три шага
  сценариев записаны как **документированные пропуски** в
  `build\e2e-artifacts\` — их надо читать вместе с числом:

  | Файл пропусков | Текст | Смысл |
  |---|---|---|
  | `skipped.log` (прогон FullCycle) | `apply --execute не запускался без -Destructive: … а исполнитель и источник кандидатов в CLI не подключены` | **настоящего удаления в прогоне не было** |
  | `skipped-undo-restore.log` | `в mrproper-cli нет команды отмены: доступны [scan, plan, apply, report, rules, disks, help]` | восстановление проверяется контрактом манифеста, а не настоящей отменой |
  | `skipped-undo-restore.log` | `дефект CLI: apply --candidates --execute при 0 операциях в плане вернул код 0 вместо 3 (Refused)` | FR-5 обходится на пустом плане — заведено как **D-49** |

* Пропуски **не молчаливые**: сценарий печатает строку, пишет её в файл и продолжает.
  Это ровно тот режим, который §11.4 и сам сценарий объявляют. Но «зелёный Pester»
  при трёх записанных пропусках читать как «полный цикл пройден» нельзя — и сегодня
  он не пройден, потому что **исполнителя удаления в CLI нет вообще** (§3.6).

* Один пропуск, который стоит назвать отдельным фактом: `apply --execute` не был бы
  запущен **и с ключом `-Destructive`**, потому что у CLI нет ни источника кандидатов
  живого скана, ни `OperationExecutor`. Ключ не передан не из осторожности, а потому
  что за ним всё равно нечего выполнять.

### 3.5 CTest без метки e2e

Отдельного прогона `ctest` без `-L e2e` в этом проходе не было: `tools\test.bat`
(без третьего аргумента) уже гоняет оба набора C++ и печатает их сводку, а правило 2
волны запрещает прямой вызов cmake-инструментов. Все CTest-проверки, которые сегодня
измерены, измерены через `tools\run-e2e.bat`.

### 3.6 Проверка CLI: манифест дошёл до потребителей

Это главное поведенческое изменение волны, и его надо показать числами, а не словами.
Проверка выполнена вручную на песочнице из трёх файлов по 64 КиБ
(`build\e2echk\junk\sub\f{1,2,3}.bin`), без `--execute`, ничего не удалявшего.

| Проверка | Команда | Результат |
|---|---|---|
| `plan` без манифеста в файле | `mrproper_cli.exe plan --candidates cand.json --json` | `operations: 1`, `untouched: []`, `byAction.trash.count: 1`; в `reason` есть строка `объём пересчитан CLI по файлам на диске` |
| `plan` с манифестом в файле | `… --candidates cand2.json --json` | `operations: 1`, `untouched: []`, `allowedCount: 3`; строки `объём пересчитан CLI` в `reason` **нет** — манифест взят из файла, а не восстановлен |
| Список разрешённого в плане | та же команда | `allowedPaths` содержит ровно три пути песочницы |
| Запрет FR-5 на непустом плане | `apply --candidates cand2.json --execute` | код **3** (`Refused`) |
| Тот же запрет на пустом плане | `apply --candidates empty.json --execute` | код **0** — **дефект, D-49** |

Две последние строки — находки этого прохода, а не подтверждения. Обе заведены в
`docs/defects.md` (D-48, D-49) и обе не мешают главному: обвязка манифеста работает
там, где манифест есть, и там, где его нет, CLI восстанавливает его перечислением
корня — с явной примесью в `reason` о том, что объём пересчитан.

Отдельно, чтобы не выглядело достижением: **`engine::CleanupExecutor` не создаётся
ни в одной точке репозитория.** Поиск по `src/`, `tests/` и `include/` даёт только
определение класса в `src/engine/executor.{hpp,cpp}` и одну строку отказа
`src/cli/cmd_apply.cpp:857`. Ни CLI, ни UI не собирают исполнитель, поэтому
`apply --execute` физически не может удалить ничего — см. §5, пункт 3 и D-50.

## 8. Как повторить

Из корня репозитория, слот — свой (обязательный, иначе агенты делят кэш CMake):

```
tools\build.bat Debug a5
tools\test.bat Debug a5
tools\run-e2e.bat Debug a5
```

Критерий задачи одной строкой (это именно та команда, которой зафиксирован вердикт):

```
cmd.exe /c "tools\test.bat Debug a5"
```

Один e2e-сценарий — третьим аргументом фильтра:

```
tools\run-e2e.bat Debug a5 e2e_FullCycle
```

Логи прогона в репозиторий не кладутся: слот `a5` и `build\` — в `.gitignore`.
Единственное, что пишется рядом с исходниками, — `build\e2e-artifacts\`, и это
**общий каталог всех слотов**: время файла важнее его содержимого.

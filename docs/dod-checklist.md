## 1. Как читать этот документ

### 1.1 Отметки

| Отметка | Значение |
| --- | --- |
| **выполнено** | Критерий закрыт, и это подтверждено проверкой, которую можно повторить |
| **частично** | Критерий закрыт в части, назван точный остаток |
| **не выполнено** | Критерий не закрыт, и отсутствие доказано по содержимому репозитория |
| **не проверено** | Проверка требует среды, которой у волны не было: чужие VM, права, диск |

Отметка «не проверено» — не то же, что «выполнено presumed». Критерий, который нечем
было померить, остаётся невыполненным до тех пор, пока его не померит тот, у кого
среда есть.

### 1.2 Источники доказательств

1. **Прогон волны (проверено здесь).** `tools\build.bat Debug a99` → `[build] ok: build\a99`,
   ни одного предупреждения; `tools\test.bat Debug a99` → `ALL PASS: 305 проверок, провалов 0`.
2. **Чтение кода (проверено здесь).** Ссылки вида `файл:строка` прочитаны в текущем дереве.
3. **Реестр дефектов `docs/defects.md` §7 (цитируется, но не перепроверялось целиком).**
   Это снимок на момент пяти проходов ревью, а не текущее состояние кода.

### 1.3 Важное предупреждение о реестре дефектов

Реестр `docs/defects.md` **устарел относительно кода** — и это установлено сверкой, а не
предположением:

* **D-09** («второй `start()` → `std::terminate`») — **исправлен**. `src/engine/executor.cpp:1685-1688`
  теперь перед созданием нового `jthread` перемещает прежний и присоединяет его под мьютексом,
  с комментарием, объясняющим, почему присваивание в joinable-поток опасно.
* **D-22** («`waitForIdle()` ждёт условие, для которого никто не даёт сигнала») — **текст
  формулировки устарел**: сигналы есть (`src/platform/inventory.cpp:1095` в деструкторе,
  `:1157` при постановке `pending_ = true`). Но остаток дефекта жив: переходы
  `busy_ = false` (`:1257`) и `pending_ = false` (`:1309`) **не сопровождаются `notify`**,
  поэтому ожидающий, зашедший в `waitForIdle()` при `busy_ == true`, всё равно дождётся
  таймаута. Формулировку реестра надо править, симптом — нет.

Отсюда правило чтения: **строку реестра нельзя переносить в DoD как есть** — её нужно
сверить с кодом. Ниже в документе такие строки помечены явно.

## 3. Пункт за пунктом

### §12.1 — Карта разделов на 3 эталонных VM

> На 3 эталонных VM (MBR/BIOS, GPT/UEFI, мультидиск) карта разделов совпадает с эталоном:
> 100 % дисков, разделов и томов, 0 расхождений по суммам размеров.

**Отметка: не проверено.**

| Что есть | Где |
| --- | --- |
| Инструмент сравнения — дамп `mrproper-cli disks --json` | `docs/SPEC.md` §7 (строка 342-343) |
| Сборка карты: `IOCTL_DISK_GET_DRIVE_LAYOUT_EX`, GPT/MBR-тип раздела, GPT-атрибуты | `src/platform/layout.cpp`, `src/platform/inventory.cpp` |
| Транспорт и слой `wmi.cpp`, `volumes.cpp` существуют | `src/platform/` |

| Чего нет | Почему это не «почти» |
| --- | --- |
| Трёх эталонных VM | Физического доступа у волны нет; в репозитории нет ни образа, ни скрипта подготовки |
| Сверки с `Get-Disk \| Format-List` | `diskpart`/`Get-Disk` не запускались: это другая машина |
| Хост **не повышен** — `\.\\PhysicalDriveN` не открывается, `disks` даёт пустую карту и код 3 | Известное поведение текущей машины; на эталонной VM с правами результат был бы другим |

**Чтобы закрыть:** три VM с правами администратора, на каждой
`mrproper-cli disks --json` и вывод `Get-Disk | Format-List`, сверка числа дисков,
разделов, томов и сумм размеров. Расхождений должно быть 0.

### §12.2 — Скан C: SSD ≤ 60 с и ≤ 25 % одного ядра, отмена мгновенна

> Скан на C: SSD занимает ≤ 60 с и ≤ 25 % одного ядра; отмена работает мгновенно.

**Отметка: не проверено.**

| Что есть | Где |
| --- | --- |
| Отмена сканера как отдельный путь | `src/engine/scan_coordinator.cpp` |
| Тест на отмену в e2е (сценарий отмены) | `tests/e2e/Test-UndoRestore.ps1` |
| Ограничение «не более 8 потоков, throttling при idle» | `docs/SPEC.md` §5; потоки в `vfs_walk.cpp` |

| Чего нет | Почему это не «почти» |
| --- | --- |
| Перф-теста и бенчмарка | В `tests/unit` и `tests/integration` нет ни одного замера времени скана; критерий нечем поддерживать в CI |
| Замера на C: SSD | Скан на этой машине идёт без прав админа и по реальному диску — замер был бы недостоверен |
| Замера «≤ 25 % одного ядра» | Инструмента замера CPU нет |

**Остаток D-22 (живой, см. §1.3):** `InventoryCache::waitForIdle()`
(`src/platform/inventory.cpp:1195-1198`) ждёт предикат `!pending_ && !busy_`, но переходы
`busy_ = false` (`:1257`) и `pending_ = false` (`:1309`) не вызывают `notify`. Любой
ожидающий, зашедший в ожидание при непустом состоянии, всегда ждёт таймаут. Для критерия
«отмена работает мгновенно» это прямое препятствие.

**Чтобы закрыть:** добавить замер с календарным бюджетом (как уже сделано в
`tests/unit/rules_fuzz_tests.cpp:942` — «корпус битого JSON не уложился в бюджет»), снять
его на C: SSD, починить отсутствие `notify`.

> Приложение запускается без повышения прав; повышение запрашивается только на операции.

нет вовсе» — но это правка спеки, а не документа.

### §12.9 — Локализация ru+en полна, нет обрезки при 150 % DPI

> Русская и английская локализация полны, нет обрезанных строк при 150 % DPI.

**Отметка: частично. Полнота — близка, обрезка — доказанно есть.**

| Требование | Состояние | Доказательство |
| --- | --- | --- |
| Каталог ru+en существует | **выполнено** | `src/ui/locale.hpp:240+` — 138 строк с русским и английским; `kStringCount` из `StringId::kCount` |
| Самопроверка полноты есть | **выполнено как механизм** | `selfCheck()` в `src/ui/locale.cpp:468-490` считает `emptyRu`, `emptyEn`, `untranslatedRu`, `untranslatedEn`, `duplicateKeys` |
| Каталог используется UI | **выполнено** | Экраны зовут `tr(StringId::…)` — например `src/ui/view_cleanup.cpp:150-167, 986-1000` |
| Модуль ядра покрыт тестами | **выполнено** | `tests/unit/i18n_tests.cpp` — 27 тестов |
| **`selfCheck()` вызывается хоть одним тестом** | **нет** | `grep -rn "selfCheck" tests/` пуст: полнота перевода **ничем не измеряется** |
| **Нет обрезанных строк** | **не выполнено** | D-29 жив: `src/ui/view_cleanup.cpp:1580` — `column.cx = 2400;` фиксированная ширина колонки, `WM_SIZE`/`LVN_GETDISPINFO` не обрабатываются, строки режутся по границе без многоточия |

Пункт «полнота» де-факто не измерен: инструмент проверки написан, но не подключён.
Пункт «нет обрезанных строк» де-факто провален: ширина колонки задана константой, а не
считается от окна, поэтому при 150 % DPI список ужимается гарантированно.

**Чтобы закрыть:** (1) вызвать `selfCheck()` из теста и падать на ненулевом
`untranslatedRu + untranslatedEn`; (2) пересчитывать ширины колонок в `WM_SIZE` и
`LVN_GETDISPINFO`; (3) добавить e2e на 150 % DPI.

### §12.10 — Установка и удаление установщиком на чистой VM

## 6. Как обновлять этот документ

1. Правка отметки делается **вместе** с закрывающим изменением: пункт не переводится в
   «выполнено», пока рядом не появляется доказательство — вывод команды, файл:строка или
   протокол прогона.
2. Отметка «не проверено» не превращается в «выполнено» по умолчанию. Превращается только
   вместе с результатом замера.
3. Строка из `docs/defects.md` переносится сюда только после сверки с кодом — реестр
   устаревает (§1.3, D-09 и D-22 как примеры).
4. Счёт «N из 12» в шапке обновляется при каждой смене отметки.
5. Новый пункт §12 в спеке добавляется в таблицу §2 и в раздел 3 этой же волной,
   вместе с правкой шапки.
